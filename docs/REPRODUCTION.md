# Reproducing the Sustainable-VEG benchmark

This guide describes the repository's shared setup, expected artifacts, benchmark commands, and evaluator. The paper reports results on all 223 annotated candidate pages.

## 1. Environment

Python 3.10+ is recommended. Create an isolated environment from the repository root:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt
```

OCR generation requires substantially more disk space, GPU memory, and model downloads:

```bash
pip install -r requirements-ocr.txt
```

Copy `.env.example` to `.env` and set only the credential needed by your chosen method:

| Variable | Used by |
|:--|:--|
| `OPENAI_API_KEY` | RAG baseline |
| `GEMINI_API_KEY` | Direct VLM and GGSR |

API-backed runs can incur cost. Check model availability and pricing in your provider account before launching the full benchmark.

## 2. Data and paths

Download the source reports from the link in [`data/README.md`](../data/README.md), place them under `data/reports/`, and verify the package:

```bash
python scripts/validate_dataset.py --check-reports
```

All path settings live in [`config.yaml`](../config.yaml) and are resolved relative to the repository root, so commands can be invoked from any working directory.

Generated artifacts follow this layout:

```text
artifacts/
├── ocr/
│   ├── chandra/<report-stem>/<page>/output.json
│   └── olm/<report-stem>/<page>/output.json
├── sasb_db/<industry>/faiss.index
└── sasb_idx/<industry>/vector_data.pkl

results/<method>/
├── prediction.csv
└── plots/                         # when generated by the method
```

These directories are gitignored.

## 3. OCR-based baselines

Generate Chandra or olmOCR output with the scripts under `scripts/ocr/`. Precomputed OCR artifacts may also be placed directly in the paths shown above.

Build the sparse and dense SASB indices:

```bash
python scripts/build_index.py
python scripts/build_database.py
```

Run BM25:

```bash
python scripts/run_bm25.py             # olmOCR
python scripts/run_bm25.py --chandra  # Chandra
```

Run dense semantic matching, optionally with the cross-encoder reranker:

```bash
python scripts/run_semantic.py --ocr olm
python scripts/run_semantic.py --ocr chandra --rerank
```

Run RAG:

```bash
python scripts/run_rag.py
python scripts/run_rag.py --chandra
```

## 4. Vision baselines

Direct continuous-coordinate VLM prediction:

```bash
python scripts/run_direct.py
```

Grid-Guided Spatial Retrieval with the paper's two reported grid resolutions:

```bash
python scripts/run_grid.py --grid_size 25
python scripts/run_grid.py --grid_size 50
```

By default, outputs are written to `results/direct/` and `results/grid/`. Move or rename a completed grid result before running a second grid size if you want to retain both files.

## 5. Evaluation

Evaluate one or more submissions:

```bash
python scripts/score.py results/grid/prediction.csv
python scripts/score.py results/bm25/prediction.csv results/semantic/prediction.csv
```

With no positional paths, the evaluator scores every `results/*/prediction.csv` it finds:

```bash
python scripts/score.py
```

The official metric is class-aware IoU-F1 at an IoU threshold of 0.5. Matching is greedy from the largest IoU downward and is performed independently for each SASB metric code. IDs are read as strings, preserving values such as `000`.

## 6. Repository checks

The same lightweight checks run in GitHub Actions:

```bash
make validate
make test
```

These commands validate annotation structure, compile all Python files, and test core evaluator behavior without downloading any model weights.

## Reproducibility note

The method scripts expose model names and operational parameters, but exact API model snapshots may be retired or changed by providers. For an archival result, record the provider model version, run date, package lockfile, hardware, prompt files, and generated prediction CSV alongside the score.
